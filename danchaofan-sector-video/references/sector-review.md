## 第一层追加 · 第 14 条：板块级数据红线（本产线最容易串口径）

板块稿有**两层数据、两套口径**，混用即数据造假。逐项回查该视频 `参考资料/抓取数据/` 下的 `sector_board.py` 输出 JSON：

**① 板块层数字**（板块涨跌幅、近 5 日/近 20 日涨跌幅、板块指数点位、成交额、板块总市值、年内涨跌幅）——回查 JSON 的板块层字段（`percent` / `period_percent` / `current` / `amount_yi` / `market_capital_yi` / `current_year_percent`）。这些是雪球官方板块指数值，稿子里的数字必须和它一致。

**② 成分层数字**（涨跌家数、涨跌停家数、主力净流入、成分股 PE 中位数、龙头市值排序）——回查 `members_agg` 字段。

**③ 个股数字**（股价、涨跌幅、市值、PE、PB）——**回查 `xueqiu_quote.py` 当日返回，不认板块脚本里的成分股快照**。

**④ 逐条核这四类串口径的写法，出现任一即打回：**

- **把成分层自算涨跌幅当板块涨跌幅念**。稿子说"板块跌了 0.47%"而 JSON 板块层 `percent` 是 +0.3%（0.47% 是 `percent_weighted`）→ 打回。`percent_equal` / `percent_weighted` 只能用来说"涨跌集中在大票还是小票"。
- **拿几只龙头的涨幅平均去代表板块涨跌幅**，或反过来拿板块涨跌幅去说某只票涨了多少 → 打回。
- **区间涨跌幅没说清交易日数**。"这周跌了 X%"必须对得上 JSON 的 `period_trading_days`；跨节假日的周里"这周"和"最近五个交易日"不是一回事 → 要么改准，要么改成"最近五个交易日"。
- **板块 PE 分位是编的**。分位接口拿不到、只能靠搜索。稿子里出现具体分位数字（"处在过去十年 15% 分位"）却在 `参考资料/` 里找不到对应搜索出处 → 打回。正确写法是如实说"这个分位我没找到准数"。

**⑤ 口播数字纪律**（账号级约定，逐句扫）：阿拉伯数字 + %，且**四舍五入到顺口量级**。❌"109 只成分股中有 53 只下跌，占比 48.62%"、❌"主力净流入 -3.25 亿" → ✅"109 家里 53 家在跌"、✅"主力资金净流出三个多亿"。

## 第一层追加 · 第 15 条：龙头点评红线（本品类最易翻车，逐句扫第 ④ 段）

分化段（五段结构的第 ④ 段）是全片信息密度峰值，也是荐股红线的高发区。**点评成分股只能落在"业务占比 / 披露口径 / 谁真沾这个逻辑"**。

**判定口诀：说清"这家的业务沾不沾这个逻辑"= 内容（放行）；说"所以这几家里该选谁"= 荐股（打回）。**

出现任一即打回，把原句抄出来 + 给改法：

- **优劣排序式推荐**：❌"这几家里我更看好思源电气""最受益的是特变电工""龙头首选国电南瑞""这三家里只有一家是真的"。
- **个股买卖判断/目标价/点位**：照通用件第 7 条办，板块稿里同样一个字都不能有。
- **给成分股下"能不能拿"的结论**：❌"手里有这几家的可以放心""名字沾的那几家该躲开"——后半句尤其隐蔽，它形式上是"揭穿伪概念"，实质是给操作指令。

✅ 合规改法（同一份事实，换成客观描述让观众自己判断）：
> "这三家的这块业务占营收分别是 68%、31%、3%。占 68% 的那家，这件事直接打在主营上；占 3% 的那家，市场按整个公司都受益给的估值，是不是给多了，见仁见智。"

**核查手法**：把分化段每一句关于具体公司的评价拎出来，问一句——**这句话的主语是"这家公司的业务"，还是"你/我该拿它怎么办"？** 后者一律打回。

## 第一层追加 · 第 16 条："蹭概念"定性红线（与通用件第 8 条同源，板块版专项）

通用件第 8 条要求"对公司的负面结论，问一句'这话被告上法庭我拿得出证据吗'"。板块稿有一个专属的高发形态：**说某公司蹭概念**。

- **必须有可查依据**：年报/半年报披露的业务占比、公司公告澄清、交易所问询函、监管处罚。依据要能在 `参考资料/` 里找到出处。
- **拿不出依据就降级为客观描述**：✅"这块业务在它营收里只占 3%，市场是不是给多了估值，见仁见智。"
- **直接骂"纯蹭概念/纯炒作/就是来收割的"即打回**——这是未坐实的负面定性，涉嫌损害商业信誉。

顺带核**板块级的负面定性**同样适用：❌"这个板块整个就是炒作出来的""这波纯粹是资金做局"→ 拿不出资金流/持仓/监管信源坐实的，降级为"从主力资金看，这波流入主要集中在几只小票上，持续性我保留看法"。

## 第一层追加 · 第 17 条：板块配置建议红线（形式上不像荐股，实质是）

通用件第 7 条扫的是**个股**买卖操作。板块稿会以另一种形态踩同一条线，全文单独扫一遍：

- ❌ **ETF 推荐**："××ETF 值得关注""跟踪这个板块最好的工具是××""搭配网格策略使用"。**ETF 是可执行的具体标的，推荐它和推荐个股在合规上是一回事。正文连 ETF 代码都不该出现。**
- ❌ **配置比例/仓位建议**："这个板块可以配 10%""值得布局一部分仓位""均衡分散摊大饼"。
- ❌ **分人群的板块建议**："刚入市的适合从这个板块开始""稳健型的可以关注这个板块"。
- ❌ **板块级择时指令**："这个板块可以开始left侧布局了""等回调再上"。

✅ 放行：讲清"这个板块为什么动、逻辑成不成立、贵不贵、该盯什么信号"，给"我个人的估值口径"（见 [sector-script-structure.md](sector-script-structure.md) 收口第三层）。

> **这几条反面例句多来自手边的参考公众号。** 参考文档是**内容结构**的参考，不是**合规尺度**的参考——抄骨架，不抄这个，一句都不能抄。

## 第四层追加一问 · 抽象落地关

通用件第四层三段自评照旧（进得来 / 留得住 / 传得开 + 对标历史 + 落档预测 + 优化建议）。板块稿在「留得住」里**追加一个必答项**：

**这条板块稿有没有把抽象板块落到具体代表股？** 逐条核：

1. **前 5 秒有没有出现代表股名字**（板块题的抽象感是 5 秒完播的头号杀手，账号正处留存衰减期，8 月 9 条稿件 5s 完播全部压在 42%~61%）。
2. **分化段是不是真的讲了 3-5 只票的业务差异**，还是只报了一串名字和涨跌幅。
3. **中段每两个连续数字后面有没有大白话落点**（板块稿的中段天生数字更密：板块涨跌 + 家数 + 资金流 + 价差 + 分位，中段是全账号共同最大流失区）。

**三条里缺任一条，第四层判「留得住 · 弱」，并在优化建议里明确给出改法。** 这一层不构成打回硬门禁，但板块稿缺这一样平均播放时长必崩——而平均播放时长是涨粉率的第一代理变量（huasheng 8.3 第一条，账号最强的一条规律）。

**封面自评追加一问**：封面大字有没有同时出现**板块名 + 一个具体实锤**（物证意象或一句锋利判断），并且**至少出现一个代表股名字**？板块本身比个股抽象一层，纯板块名的封面点击必崩（对照茅台抽象意象 4.90% 的教训）。

## 派子 agent 时的输入清单（比个股稿多两样）

通用件要求喂四样输入。板块稿喂**六样**：

1. 定稿全文（含选定标题、封面方向）。
2. 蛋炒饭受众画像与心声。
3. 阶段一抓到的**板块行情（`sector_board.py` 的两层 JSON）+ 龙头个股行情（`xueqiu_quote.py`）+ 板块情绪摘要**——数据红线要逐个数字回查，没有原始数据就没法核。
4. 账号 Memory `$WORKSPACE/huasheng.md` 第八节「流量认知与爆款预测」。
5. `$DESK/references/script-review.md` 的四层清单。
6. **本文件**（板块专属第 14-17 条 + 第四层追加一问）。

给子 agent 的判决要求照旧：**PASS**（前三层全过，逐项写结论不是"都过了"三个字）或**打回**（原句 + 病灶 + 改法），第四层的爆款预测与优化建议必须随判决写出来。
