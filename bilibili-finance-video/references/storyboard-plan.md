# 分镜规划方法论（知识类视频通用 · storyboard_plan.md）

把一支已定稿的口播稿翻译成分镜规划书 `storyboard_plan.md`，交下游成片引擎自动成片。本文件是这一步的完整判断逻辑：核心模型（素材类型 × 组织形式）+ 成片需求 + Method 五步 + 输出模板。

**本文件是「知识类视频」通用框架，不绑定任何单一账号/品类。** 账号级的风格、画风、素材禁忌、默认素材通道，一律由「本次输入」提供，不硬编码在本文件里。未来扩展到别的品类时，改的是「本次输入」，不是本方法论。

---

## 总心法（先读这条，其余规则都是它的展开）

**画面是一条独立于口播和字幕的信息轨道。它的职责是「补口播之未尽」，不是「复述口播之已言」。** 口播已说清、观众听音频看字幕就懂的内容，画面再用文字或图形复述一遍，等于零信息增量——显得呆、廉价、像唱和声。画面真正该干的：补上口播因口语节奏来不及展开的信息，或把抽象、陌生、复杂的东西变得可感。

**最致命的失效模式是「图解文字」——贴着台词的字面走，而没有穿过文字去够它背后真实的东西。** 写每一镜画面前，先自问一句：

> 这句口播背后，观众真正**应该看到**的现实、事件或情绪是什么？

字面主义在三个层级反复犯，全文规则逐层对治：

- **抽象层**——检索写品类筐、不落具体实体 → 对治见步骤二「两条写法规则」；
- **图示层**——把句子结构画成 MG、实拍已讲清还叠图解 → 对治见步骤四 Q1 护栏；
- **意象层**——拍字面喻体、不拍喻体所指 → 对治见步骤五「视觉概念三问」。

> 与「声画一致硬规则」（步骤五）不矛盾：「不复述」针对的是零增量的文字复述；数字 / 专名逐字一致是信任底线。信息增量靠坐标补全、人物身份卡、名场面联想来实现。

## 0. 核心模型：素材类型 × 组织形式

一个分镜画面只由两件事决定，两轴叉乘覆盖一切，不需要再给任何组合起名字：

1. **素材类型（`material`）**——这镜用了什么素材、从哪条通道来。
2. **组织形式（`form`）**——这些素材（或没有素材）是怎么被组织成画面的。

### 0.1 组织形式（`form`，三档）

统一原则：**MG 的本质 = 用 HTML 代码构建画面**。HTML 可以嵌入素材（`<img>`/`<video>`），也可以直接用代码画动画（svg / canvas / css）。于是 form 三档，对应信息抽象度的三档阶梯：

| form | 生产定义 | 信息抽象度 | 认知任务 |
|---|---|---|---|
| `raw` 单素材 | 不写 HTML，素材文件直接上屏 | 放「实物」 | 给真实感 / 情绪 / 呼吸 |
| `mg-compose` MG 组织素材 | 写 HTML，把素材嵌进去排布 / 叠加 / 编排 | 摆「关系」 | 把素材之间的关系画出来 |
| `mg-pure` 纯 MG | 写 HTML，不嵌素材，纯代码画 | 造「抽象」 | 画现实里没有对应画面的东西 |

`mg-compose` 内部两个子形态（**不单列枚举**，由 `material` 基数 + 画面描述共同表达）：

- **叠加层（overlay）**：1 个素材垫底，上面叠一层 MG（动态数字、图表、标签、大字报）。
- **编排（arrange）**：多素材被 HTML 编排（并列 / 快切 / 框架 / 时间轴 / 多宫格）。

**判断问句（每镜问一句）**：这一镜观众要看到的是「一个实物」「几个实物之间的关系」，还是「一个没有实物的抽象」？

### 0.2 素材类型（`material`，七类通道）

素材的画面表现价值，本质只有四类——观众看这张画面时得到了什么：

| 价值 | 观众得到 | 对应素材 |
|---|---|---|
| **真实感 / 证据感** | 「这是真的、这是正在发生的现实」 | 云端库、websearch、本地 |
| **人格 / 信任 / 态度** | 「是这个人说的、他负责、他的态度」 | a-roll |
| **情绪 / 共鸣 / 网感** | 「情绪被戳中、我懂」 | 表情包、（a-roll 微表情） |
| **可控 / 补缺 / 一致性** | 「现实没有的画面，被造出来了」 | 生图、生视频、（纯 MG） |

七类素材逐类——**画面表现价值 + 何时用 + 风险**：

| code | 素材类型 | 画面表现价值 | 何时用 | 风险 / 慎用 |
|---|---|---|---|---|
| `a-roll` | 真人出镜 | 人格与信任。唯一能传语气 / 微表情 / 态度的画面，把「信息」变成「这个人亲口对你说」 | 态度落点、表态担责、人格开场、互动结尾；**是锚点不是主体** | 信息密度为零（脸不传数据），连续露脸显说教 |
| `local` | 本地上传素材 | 独家真实感 + 版权安全。指定地点 / 独家画面，检索拿不到 | 有独家素材（探访 / 实拍某具体地点）时**优先用** | 量有限、覆盖面窄、前置成本高（得先去拍 / 收集） |
| `cloud` | 云端素材库 | 真实感底色 + 量。海量真实世界视频 + 空镜，已索引、随取随用 | 全片真实感底色，`raw` 主力来源 | 检索精度（未必对上具体内容）、版权（二次使用）、画质参差 |
| `web` | websearch 时效素材 | 证据感 + 当下感。新闻标题 / 财报 / 数据截图，给事实陈述背书 | 要「当下 / 证据」时 | 检索**对不上「具体主体 × 具体时刻 / 具体数值」**（这类必错）、版权、时效一过就废 |
| `gen-img` | 生图素材 | 可控补缺。给「搜不到 / 拍不到」的画面一个指定且风格可控的版本，还能对齐 MG 画风 | 「检索不到」的空缺、需要风格统一的视觉母题 | AI 味、真实性争议（新闻类不能生成假照片冒充真实）、质量不稳 |
| `gen-vid` | 生视频素材 | 叙事一致性。叙事段要「同一主体连续演下去」时唯一能保证连贯 | **最后手段** + 叙事一致性刚需 | **最贵**、AI 味最重、生成最不稳 |

**升级阶梯**（真实感场景，默认从最便宜可靠的通道起，不够才往上加钱）：

> 有 `local` 独家 → **优先 local**（独家 > 通用）→ 否则真实感默认 `cloud` → 要「当下 / 证据」才上 `web` → 检索不到才 `gen-img` → 叙事一致性刚需 / 实在找不到才 `gen-vid`。

**通用硬规则（检索对不上的那类画面）**：凡涉及「具体主体 × 具体时刻 / 具体数值」的画面（例如某只股票某天的走势、某个具体股价数字），`cloud` / `web` 都**检索不到对的那一张**——禁止把这类画面当检索目标。落法分两档：

- **数据卡型（默认，走 `mg-compose`）**：只是要把口播里那个具体数字 / 简单图表打上屏——用一张**通用**底素材（`cloud` 空镜等，与具体数值无关）衬底 + 代码画数字 / 柱状 / 曲线。这不违反上一条：被禁的是「拿具体数值去检索素材」，不是「通用底图 + 代码层」。底图也可省略、纯色底 + 代码（此时 `material` 为空、form 记 `mg-pure`，但仍属数据卡、不占高光额度）。
- **框架型（走 `mg-pure`，全片 1~3 个高光点）**：要装下一整段时序 / 机制 / 对比的完整框架画面（传导链、时间轴、多空对比框架），才用纯代码画。

若非要配「长得像真的」的具象图，只能 `gen-img` 指定生成。这是一条通用规则，不限于财经。

### 0.2.1 `a-roll` 专项（真人出镜的判定与拍摄规格）

`a-roll` 是唯一需要「拍摄规格」的素材类型（其他素材是检索 / 生成），也是唯一能传人格与态度的画面。单独给它一条判定与规格规则：

- **判定问句**：**「这一镜观众需要看到『是谁在说』吗？需要我这个人站出来表态、担责、拉近距离——就上 `a-roll`；只需要信息本身——就交给素材和 MG。」** 一句话：**讲信息 → `cloud`/`web`/MG；讲态度、讲「我」→ `a-roll`。**
- **正面清单（满足其一即上 `a-roll`）**：① 品牌锚 / 人格开场（**开场露脸以 `mg-compose` 落地**——a-roll 垫底 + 标题 / 大字报叠加，不做纯 `raw` 露脸开场，与步骤四「S01 禁止 `raw` 开场」硬规则一致）；② 转场 / 悬念 / 卖关子；③ 态度 / 情绪落点；④ 第一人称观点 / 判断 / 表态（「我」「我不」「我给你」「我提醒你」——`a-roll` 最核心的用武之地）；⑤ 互动 / CTA 结尾。
- **反面清单（别硬上）**：纯数据 / 纯事实陈述；连续多镜堆露脸；任何「画面本身在传信息」的地方。
- **露脸镜的 form 表达**（三种，都是 `form` × `material` 的普通组合，**没有独立的 `a-roll+mg` 类型**）：
  - 纯露脸口播 = `form: raw` + `material: ["a-roll"]`。
  - 露脸垫底 + MG 叠加（点缀图标 / 分屏数据 / 大字报）= `form: mg-compose` + `material: ["a-roll"]`——overlay 子形态：a-roll 是那 1 个垫底素材，MG 叠在上面。
  - 露脸垫底 + 再嵌其他素材 + MG（主播半身垫底，旁边并列财报截图 / 数据卡）= `form: mg-compose` + `material: ["a-roll", "web"]`——arrange 子形态：多素材编排，编排关系写进 `visual_description`。例：「底为主播半身正面（`a-roll`），右侧嵌入财报截图（`web`）暗化作衬，顶部净利数字从 0 滚到口播所念数值，念到『没那么糟』时截图边框高亮。」
- **频率**（仅当「本次可用素材类型清单」含 `a-roll` 时适用；不含则全片不露脸、本条不生效）：`a-roll` 是锚点不是主体，每个逻辑章节开头 / 收尾各一次即可；**露脸密度（`a-roll` 分镜数 / 总分镜数）合理值 20%~30% 上下**——统计口径：**凡 `material` 含 `a-roll` 的分镜都计入**（纯露脸 `raw` 和露脸垫底的 `mg-compose` 都算，只要观众在这镜看到人）。低于人格感不足，高于说教感重；超了把部分露脸镜降级回素材 / MG。
- **拍摄规格（`a-roll` 分镜的 visual_description 要写）**：景别（近景 / 半身 / 特写）、机位（正面对镜 / 侧四十五度）、情绪标签（克制陈述 / 语气加重 / 反讽 / 客观平衡）、是否用提词器。例：「主播半身正面对镜，提词器辅助，语气克制不带情绪——念到『那是情绪』时微微摇头。」

### 0.3 两轴耦合约束（两轴不是自由叉乘）

| form | material 基数 |
|---|---|
| `raw` | 恰好 1 个 |
| `mg-compose` | 1 个或多个（各自类型可不同） |
| `mg-pure` | 0 个（空） |

### 0.4 两问决策（每镜，先 form 后 material）

- **Q1 定 form**：观众要看到「一个实物 / 几个实物之间的关系 / 一个没有实物的抽象」？→ `raw` / `mg-compose` / `mg-pure`。
- **Q2 填 material**：这镜要传「真实感 / 人格 / 情绪 / 补缺」里的哪个价值？去对应池子按升级阶梯取：
  - 真实感 → local（有独家）→ cloud（默认）→ web（要证据）→ gen-img（找不到）
  - 人格 → a-roll
  - 情绪 → meme（小剂量）/ a-roll（微表情）
  - 补缺 / 一致性 → gen-img → gen-vid（最后手段）

> **本次可用素材类型约束**：Q2 里 material 的取值**只能来自「本次可用素材类型清单」**（见 §A 输入）。清单里没有的类型，即使按价值判断想用，也不能用——改用清单内最接近的类型，或升级到 `mg-pure` 用代码画。

## A. 定位与触发 + 输入

- **触发时机**：封面产出后停下，用户明确说"做分镜/做成视频"才跑；也支持独立入口（见 §A.1）。
- **输入（五样）**：
  1. **口播稿**——唯一真源，是要被切分的正文，逐字照切、绝不改字改标点。
  2. **本次可用素材类型清单**——**每次 plan 前由上游 / 用户指定**：本次有哪些素材类型可用（`a-roll` / `local` / `cloud` / `web` / `meme` / `gen-img` / `gen-vid` 的子集）。**每次不一定全有**。来源：用户口头指定，或文档里的一行「本次可用素材类型」。未指定时默认**全部可用**，但 material 选择仍需按升级阶梯（默认最便宜可靠的）。
  3. **封面 / 风格说明**（可选）——用来对齐画风的情绪偏移，并提取本期视觉母题（见 §F）。
  4. **元信息头**——拿标题、主体名等。
  5. **证据清单**（可选）——`参考资料/证据截图/证据清单.md`。每条是一张权威出处的真实截图（财报高亮、政府公告、官方媒体或证券报首屏、研报结论），并写明对应的稿中原句。切到那句口播时，优先用这张截图做 `local` 素材的新闻引文 / 报告高亮镜头，在画面描述里写清文件名；不要再让下游生成一张假的财报或新闻截图。清单顶部「待补权威信源」里的说法没有截图，不要配截图类镜头，用自制数据卡或纯口播。
- **产物**：同目录 `storyboard_plan.md` + `storyboard_plan.html` 两个文件（html 由工具脚本生成，见 §H）。
- **A Roll 是否在清单里**：`a-roll` 就是素材类型之一，不再单设「是否露脸」的开关。清单里有 `a-roll` → 本次可以有露脸镜；没有 → 全片不露脸，照常产出（不自作主张加露脸镜）。

### A.1 独立入口 / 无封面降级（外来稿直接做视频）

本步不一定从走完前置阶段的文档进入。用户拿一份**现成口播稿**直接说「把这份稿做成分镜」时，也从这一步单独进：

- **唯一硬输入是那份口播稿正文**——逐字照切、绝不改字。标题 / 主体名若稿里没有，就从正文提炼或问用户一句。
- **「本次可用素材类型清单」仍需指定**（用户口头给，或问一句「本次有哪些素材可用」）；不指定则默认全部可用。
- **没有封面时走「无封面降级」**：唯一受影响的是视觉母题与情绪偏移——视觉母题不再「沿用封面核心意象」，改为从稿子主体（核心主体 / 论点）提炼（方法见 §F，只是换个来源）；情绪偏移从稿子本身的内容情绪取。**其余（核心模型、Method 五步、两问决策、输出模板）全部照常，不受影响。**
- **落地位置**：有 `视频基础信息.md` 就同目录落 `storyboard_plan.md` + 补指针小节；走独立入口没有该文档时，直接落在来源稿同目录（或用户指定目录），不强行补建整套文档。

## B. 制作方案（不再固定「方案 B」）

知识类视频的画面天然需要 form 三档齐备——`raw` 给真实感呼吸、`mg-compose` 摆关系、`mg-pure` 造抽象。**不存在「选 A 还是 B」的二元选择**；三档的比例由内容形态决定（纯讲解抽象概念的片子 `mg-pure` 占比自然高，实地纪实为主的片子 `raw` 占比自然高）。本账号 / 本品类若有倾向，写进「本次输入」的素材要求里，不硬编码进方法论。

## C. 成片需求（风格 / 画风 / 母题 / 禁忌 → 本次输入）

`storyboard_plan.md` 第一节写这份成片需求。字段照下面填，**带 `〈本次输入〉` 标记的字段由上游 / 用户提供，不写死**：

- **📋 基础信息**
  - 视频标题：= 定稿的最终标题
  - 内容摘要：100-150 字，讲清这条视频的核心判断
  - 画幅 / 主发平台：〈本次输入，如「9:16 竖屏（抖音主发）」〉——**决定一切构图**：竖屏时视觉重心放在画面上 2/3、底部约 1/4 留给自动字幕不许压 MG 大字报、多素材编排优先上下堆叠而非左右并列/多宫格
  - 年代背景：按稿子实际（现代 / 某段历史）
  - 参考风格：〈本次输入，如「深度解说」「严肃调查」「轻科普」〉
  - BGM 需求：一句自然语言，贴合稿子情绪
- **🎥 素材要求**
  - 本次可用素材类型：〈回填清单，如 `cloud` / `web` / `meme` / `gen-img`〉
  - 素材偏好：〈本次输入，如镜头偏好、画面留白给 MG 叠加、避免素人正脸等〉
  - 素材禁忌（硬规则）：〈本次输入的最高优先级禁忌〉。通用硬规则（§0.2「具体主体 × 具体时刻 / 数值检索必错」）始终生效，无需重复。
  - 时效性：〈本次输入，如「使用近 X 年素材」〉
  - 地域 / 范围：〈本次输入，按视频主体〉
  - 专名要求：〈素材中应出现的主体名 / 核心名词〉
  - 用户硬性要求：〈原文转述，无则写「无」，最高优先级〉
- **🎨 画风**（双层模型，见 §F）
  - 账号固定层：〈本次输入，账号识别度骨架：色板 / 字体 / 图标风格 / 构图气质〉
  - 情绪偏移：〈按本条稿子，在固定层之上微调温度〉
  - 视觉母题（本期共振）：〈一句话——母题是什么 + 怎么用；优先沿用封面核心意象〉
  - MG 组件：〈本期用到的重复 MG 组件清单；账号固定组件（如 CTA 卡）原样继承，本期新增的在 `mg_components` 里定义，见 §E〉

紧跟一段机读 `global_style`（下游取值参考，具体枚举值受下游资产库约束，取列表内最接近项，实测校准）：

```json
{
```

## D. Method 五步

**粒度总则：画面是分镜的属性，不是场景的属性。** 一段连续叙事内部往往是：平陈述（`raw`）→ 砸一个数字（`mg-compose`）→ 继续背景（`raw`）。画面价值的触发点是「这一刻 / 这一句」级的，落在分镜上。所以 **`form` 与 `material` 都定在分镜，一镜一给**；场景退化成「检索批次 + 画面一致性底线」，只背一份共享的检索上下文，以及一张「不许跑偏」的画面一致性底线（影调 / 母题 / MG 大风格），不背画面细节。

动笔前先按三层拆稿看清每段在干什么：**内容层**（客观事实、陈述）、**认知层**（观点 / 数据 / 逻辑）、**结构层**（开头钩子 / 转场 / 收尾）。这三层是帮你在分镜上判断「画面价值」的镜头。

### 步骤一：场景划分（素材检索批次）

**场景 = 一个素材检索批次**，不是画面单元。通读全稿，把连续、共享同一批检索上下文的叙事归为一个场景。

- **切场景的充分条件**（满足任一才切）：**叙事主体切换**（换一个主体 / 换一个论点主体）/ **素材来源切换**（从一类素材转到另一类）。
- **不该切**：画面在变、情绪在变，但检索的还是同一批素材——不切；起伏交给分镜层的 form 去表达。
- **不再为「隔离一个数字」硬切小场景**——那个数字的强调由所在分镜升级成 `mg-compose` / `mg-pure` 解决，与场景无关。
- **场景长度**：一个检索批次通常 100~300 字，不设硬上限；真正的硬约束是**每场景最多 10 个分镜**（超了拆两个场景）。
- **编号**：A01、A02…，每场景一个简短 `scene_title`。

### 步骤二：场景设计要求（scene_design）

每个场景一段，是给下游的「场景执行摘要」（下游看不到全稿）。它有两个消费者、两段内容：

**① 检索上下文**（给检索服务，material 非空的镜消费）——四要素：

- **专名清单**：列场景内专名，格式 `专名（类型）`，代词消歧 `"代词"→专名`；**主体名必须在这里出现**。无则写「无」。
- **范围 / 年代**：〈按视频主体，如「范围：某国 / 年代：现代」〉。
- **素材来源**：具体作品名 / 资料类型；泛泛的「素材」不算。**禁止写「具体主体 × 具体时刻 / 数值」的检索词**——这类检索必错（见 §0.2 通用硬规则），改由数据卡（`mg-compose` 通用底 + 代码数字）、框架型 `mg-pure` 或 `gen-img` 解决。
- **素材偏好**：镜头 / 风格偏好 + 禁忌。

两条写法规则（写上面四要素时遵守，防「抽象层」字面主义）：

- **具名实体，枚举不归纳**：检索词必须落到画面辨识度高、库里能搜到的**具名实体**——品类词搜不出东西。反例「新能源汽车的素材」→ 正例「特斯拉上海工厂产线、比亚迪交付中心、充电桩特写」。
- **抽象判断句 → 观众第一联想的名场面**：台词下抽象判断（「全行业产能出清」「市场恐慌」这类）时，检索锚不用抽象词——先想观众聊起这个概念时脑子里第一时间浮现的**真实名场面**是什么，用它做锚（「产能出清」→ 工厂关停、商铺转让告示；「市场恐慌」→ 交易所大屏一片绿）。利用的是观众对一件事的集体刻板印象，这是最有说服力的视听语言。

**② 画面一致性底线**（给分镜执行，所有镜消费，`mg-pure` / `mg-compose` 尤其）——只写「本场景相对全局画风的偏移」，全局已有的（色板 / 字体 / 图标 / 全片母题 / 全片情绪偏移，都在 §C）**不在此重复**：

- **场景情绪 / 影调**：本场景相对全片温度的偏移（开场更锐、呼吸段更暖、看跌段更压暗）；含本段口播语气基调（克制陈述 / 语气加重 / 反讽），喂给场内 `a-roll` 镜。
- **母题落地提示**：母题在本场景的变体（全片一致则省略，只在变体时写）。
- **MG 风格基调 + 动效节奏**：本场景 MG 的统一视觉处理（如「本场景数据图统一深色底 + 柱状」）+ 时间维度的动效基调（信息高潮段动效快、密度高；呼吸段缓、少动）。
- **raw 镜头感**：本场景 raw 素材的镜头语言（硬朗快切 / 舒缓呼吸 / 压暗审视）。
- **生成一致性锚**（场内有 `gen-img` / `gen-vid` 镜时必填，否则整项省略）：主体外观锚（服装 / 形态 / 环境的 canonical 描述，供场内多个生成镜复用，防止各画各的）+ 生成风格词（写实 / 插画 / 光影质感，保证同场景生成画面不跳风格）+ 负面约束（本场景不得出现什么）。
- **语义色约定**（可选）：本场景的强调色 / 配色语义偏离全局时才写（如「本场为下跌段，强调色切绿」）。

> **写到不变量为止**：场景只背「不许跑偏」的底线（影调 / 母题 / MG 大风格），具体画面起伏仍交给每个分镜的 `visual_description`。`mg-pure` 镜没有 material，检索四要素对它无用——它吃的是这一段；`meme` / `gen-img` / `gen-vid` 也主要靠这一段拿情绪指向与生成风格锚点。新增字段同样遵守省略原则：全片一致就省略；生成一致性锚在没有 `gen-*` 镜的场景整段省略。

### 步骤三：分镜断句（Shot）

对每个场景，把它那段口播切成分镜。

**首要准则：一个分镜 = 一个完整独立的画面 + 一段自足的语义。** 切分镜的问题不是「这里有没有标点」，而是「**这一句念出来，脑子里换不换一个新画面 / 是不是一个能独立成立的意思**」。换画面、进入一个新的独立意思，才切下一镜；同一画面、同一意思的延续（哪怕跨标点）留在一镜。**宁长勿碎**。

- **判断切点**：问「下一句是不是要换画面 / 起一个新的独立意思」。因果、转折、并列这些为同一个意思服务的复合结构，整体留在一镜；一个数字 + 它的解读、一个名词 + 它的定义，算一个自足语义单元，不拆开。
- **字数是护栏不是依据**（不含标点，只算念出来的字）：
  - `raw` / `mg-compose` 分镜：一个自足画面通常 **15~50 字，平均 30 字上下**。<12 字且语义不自足 → 与相邻同画面分镜合并；>50 字 → 多半塞了两个画面 / 两个意思，在画面切换点拆两镜。
  - **框架型 `mg-pure` 分镜是例外，可以更长（60~120 字）**：它本身就是一个装了一整段时序 / 对比 / 机制的框架画面，口播天然更长。这不是「塞了两个画面该拆」，它就是一个画面。只有当框架实在装不下（要素超多、逻辑分岔）时才拆。
- **数量**：不设下限；**唯一硬约束是每场景最多 10 个分镜**。
- **编号**：S01、S02…（全篇顺序）。
- **完整性约束**：分镜 `script` 只能从口播稿原文「切」出来——不遗漏、不新增、不改任何一个字或标点。合并 / 断句只改「在哪里切」，绝不改字。唯一例外：独立组件镜（章节卡 / 转场卡 / CTA）允许 `script: ""`（见 §E 字段约定）。

### 步骤四：分镜 form + material 判定（两问决策）

对每个分镜，按 §0.4 的两问决策给 `form` 与 `material`：

- **Q1 定 form**：观众要看到「一个实物 / 几个实物之间的关系 / 一个没有实物的抽象」→ `raw` / `mg-compose` / `mg-pure`。**护栏（防「图示层」字面主义）**：实拍素材本身已承载的内容，别再升 `mg-compose` 把句子结构图解一遍——MG 的职责是总结 / 补充 / 辅助理解（补全口播没空展开的全称、数据、多分支逻辑），不是把台词做成文字砸屏；观众听得懂的复述 = 零信息增量。
- **Q2 填 material**：按价值取向去对应池子，按升级阶梯取，且**只能取「本次可用素材类型清单」内的类型**。拿不准时问一句：**「这一镜如果只用最便宜可靠的素材，观众会不会看不懂、或觉得平而划走？」**——会，就升级（升级 = 换更贵的通道，或升到更高信息抽象度的 form）。

**节奏原则（贯穿全片，定完类型回头扫一遍分镜序列）**：

- **开场硬规则**：S01 必须是 `mg-compose` 或 `mg-pure`（大字报 / 核心冲突数据砸屏），**禁止 `raw` 空镜开场**；前 3 个分镜内必须出现本期核心矛盾的可视化。3 秒留不住人，后面做得再好也没人看。
- 知识类视频的观看曲线：`raw` 给呼吸、`mg-compose` / `mg-pure` 给信息密度。密度不是越高越好，过度密集 → 廉价堆砌、观众疲劳。**MG 密度随题材走**：数据 / 对比 / 流程多的题材可以密，纯叙事 / 抒情 / 历史故事类应当稀疏、大量用实拍承载；不为「显得丰富」给每镜都上 MG。
- 分布呈「**两头重、中间点缀**」：开场与收尾舍得上 `mg-compose` / `mg-pure`，中间以 `raw` 为底、每隔一段用一个 `mg-compose` 提神，**避免连续 4 个以上 `raw` 分镜堆叠**。
- 建议判定顺序：先按位置价值锁定「开场 / 信息高潮 / 收尾」的 `mg-compose` / `mg-pure` → 再扫全稿逐镜标出该强调的数字 / 名词 / 金句给 `mg-compose` → 其余默认 `raw`。

### 步骤五：分镜画面描述（依 form，逐镜写）

每个分镜一段画面描述，依它的 form 写。`mg-compose` / `mg-pure` 本质是「HTML 代码画面」，描述要把**代码里装了什么、怎么动**讲清楚。

**五要素固定顺序**（`mg-compose` / `mg-pure` 的画面描述按此行文，要素可省略但顺序不可乱；`raw` 只需 ①②）：

> **① 视觉概念**（一句话：这句口播翻成什么装置 / 隐喻 / 器型）→ **② 底与质感**（什么素材垫底、标通道，什么质感处理：压暗 / 虚化 / 做旧 / 网格衬底）→ **③ 主体与构图**（画面主角是谁、在什么位置、点什么器型名）→ **④ 信息层**（屏显文案与数据、高亮哪一笔、声画同步点、坐标补全）→ **⑤ 动效节奏**（怎么动、念到哪句触发什么）

配套规则（第一条是写 ① 视觉概念前的必过三问）：

- **视觉概念三问（防「意象层」字面主义）**：
  1. 这句是不是**纯修辞比喻**（「风口的猪」「割韭菜」这类没有事实指涉的情绪载体）？→ 拍喻体**所指**，绝不拍字面喻体（「割韭菜」→ 营业部散户盯盘、账户一片绿的现实影像，不拍韭菜地）。
  2. 这句是不是**字面解释不通、但作者默认观众懂**的说法？→ 先核查它在现实中的指涉（真实事件 / 知名梗 / 全文 call back），据实配画面（「9·24 之后全变了」→ 核查指向当日政策发布会与行情名场面，配真实画面，不画日历）。望文生义、断章取义地配素材，是最容易闹笑话的。
  3. 这句是不是**煽情句**？→ 配图目标是情绪共鸣而非信息传达，选情绪浓度最高的真实影像，让画面替观众动容。
- **装置隐喻优先**：抽象判断句（「营销狂欢」「换游戏规则」「用脚投票」这类）优先翻成一个具体装置——手机 mockup 里演一出红包对话、旧规则清单被逐条划掉、方向相反的脚印箭头——而不是默认「底 + 大字报」。大字报是兜底器型，不是默认器型。
- **器型命名制**：构图直接点器型名，不写「上下堆叠、逐条高亮」这类泛词。常用器型词表：**数据大字报 / 双栏对比卡（两主体并排、只高亮关键行）/ 票据式排行榜（当前主体整行高亮，可外挂时间轴）/ 地图标注（区域高亮 + 主体圆标气泡）/ 时间轴（单轨，或上下双轨做前后对比）/ 拼版（照片 × 数据多宫格错位拼接）/ 流程传导链 / 装置隐喻（道具 mockup 演戏）/ 序列快切（多素材依次满屏接力、按口播锚点硬切，即 arrange 子形态的「快切」）/ 人物身份卡（肖像 + 中英文名 + 头衔，人物首现专用，规则见下）**。说「双栏对比卡，只高亮净利率那一行」下游能直接执行；「堆叠高亮」只能自由发挥。
- **坐标系补全**：凡数据卡，强制自问「除口播念的数字外，画面能不能多给一个坐标——行业排名 / 对手值 / 历史值 / 迷你趋势线」？能就给，写进信息层。口播给一个数、画面给这个数在行业里的位置，是分镜信息增量的主要来源。补的坐标必须服务口播论点，不堆无关数据。
- **人物身份卡（人物首现 = 建立身份，不复述言论）**：说话人 / 关键人物（企业家、学者、历史人物）首次出现时，画面主体是这个人的肖像 + 中英文名 + 2~3 个最有分量的头衔（如「Warren Buffett｜伯克希尔·哈撒韦董事长」），回答「他是谁、凭什么值得听」——他说了什么观众听得到，他凭什么值得听只有画面能补。肖像取权威、可辨识的信源；之后再次出现不重复建卡。
- **主语完整（信息层硬规则）**：画面里的数据、图表、变化必须写清主语，不留指代悬空。反例「两条曲线一升一降」（谁的？）→ 正例「上线：该公司营收（亿元）；下线：行业均值」。

**先查组件注册表（`mg_components`，§E）**：跨场景重复出现、样式必须统一的文字类 MG（章节卡 / 数据大字报 / 图表族 / 标签条 / 引用卡 / 金句卡 / 流程图 / CTA 卡），在 JSON 顶层注册表**只定义一次**（版式 / 动效 / 来源）；分镜描述**按名引用 + 只填本次变量**（文案 / 数字 / 数据），不重述样式——重述必然漂移。一次性 MG 不进表；某个 MG 第二次出现时，回填进注册表、改按名引用。章节卡默认叠在章节首句口播上（标题作为 MG 层）；需要硬停顿换气时才独立成镜（`script: ""`）。

**声画一致硬规则**（`mg-compose` / `mg-pure` 通用）：画面上出现的所有数字、日期、专名，必须与该镜 `script` 里口播念的**逐字一致**——口播说「蒸发了三百多亿」，画面就打「三百多亿」，不许打口播没念的精确值（如「347.2 亿」），声画打架比不打数字更伤信任。

**构图跟着画幅走**（所有 form 通用）：竖屏（9:16）时视觉重心放画面上 2/3，底部约 1/4 是自动字幕区、MG 大字报与关键图表不许压上去，多素材编排优先上下堆叠而非左右并列 / 多宫格；横屏（16:9）无此限。

- `raw`：写这一镜该配什么素材（按 `material` 的通道检索），一句话说清「什么内容 + 什么镜头感」——即五要素的 ①②，真实素材缩框居中或满屏、影调怎么处理。

- `mg-compose`（HTML 嵌素材）：按五要素写，② 里**每份嵌入素材标清通道**（`cloud` / `web` / `gen-img` …），多份素材在 ③ 写清编排关系（对照 / 递进 / 快切 / 拼版位置）。
  - 例：「① 把『翻倍』翻成碾压式对比。② 底为财报截图（`web`）压暗虚化作衬。③ 双栏对比卡，左本公司右行业均值。④ 信息层：同比增速从 0 滚到 +21%，行业均值 +8% 压灰作坐标。⑤ 念到『翻倍』时我方柱体拔高、整组放大定格。」

- `mg-pure`（纯代码画，无外部素材）：按五要素写，② 写质感处理（纯色 / 网格设计稿底 / 母题底纹），③④ 写清代码画出的内容（趋势曲线、机制 / 流程图、拓扑、时间轴、装置）。
  - 例：「① 资金传导链装置。② 深色网格底。③ 三节点 + 两根箭头从左到右排布，流程传导链器型。④ 节点标『房企→建材→下游』，当前传导到哪环哪环高亮。⑤ 箭头随口播逐节生长，念到『传到下游』时第二根箭头高亮、终点节点放大。」

- **共振层带入**：`mg-compose` / `mg-pure` 的描述里，**自然带进本期视觉母题**（§F）——作为底纹、点缀、转场或图标灵感，别硬塞、别盖掉主风格。

## F. 画风双层模型：账号固定层 × 本期共振层

成片的画风要同时做到两件事——**让观众一眼认出「这是谁」**，又**能感到「这套风格和这期内容有关」**。拆成两层：

**① 固定层 · 账号基因（永不变，是识别度骨架）**

账号画风基因（色板 / 字体 / 图标风格 / 构图气质）由**本次输入提供**，每期原样套用，不换色板、不换主字体、不换图标风格。这是系列识别度的来源。本文件不写死任何账号的基因——换个账号，换的只是「本次输入」里的这一层。字体内部分工：**功能性文字**（正文 / 说明 / 数据标注）优先可阅读性，用无衬线黑体；**装饰性文字**（标题 / 金句）追求版式美感，可用衬线宋体 / 楷体；总量控制在三个槽位以内（`global_style` 的 title / body / number 三槽天然对应），多则乱。

**② 共振层 · 本期视觉母题（每期变，是内容适配）**

在固定骨架之上，为本期提炼**一个具象「视觉母题」**——一个能代表这支视频主体的意象 / 纹理 / 符号，作为 MG 的辅助纹理、转场元素、点缀色来源或图标灵感，贯穿全片。形态四选一（或组合）：**反复出现的图形母题**（如「悖论 = 反向双箭头 / 裂缝」）/ **章节计数徽章** / **首尾呼应的叙事锚点** / **统一的底纹质感**。让观众下意识觉得画面「长得像这次的内容」，但不动主色板与主字体，不喧宾夺主。

- **怎么提炼**：从本期主体 / 核心论点里找一个最有代表性的具象符号或隐喻。**优先直接沿用封面已用到的核心意象**（封面 → 成片连贯）。**无封面降级（§A.1）**：从稿子主体提炼，方法一样、来源换成稿子。
- **怎么落地**：作为 MG 的底纹、分割线、转场动画、数据图形的形状语言或点缀图标，弱处理、不抢主信息；写进 🎨 字段一句话，并在各 `mg-compose` / `mg-pure` 分镜的画面描述里自然带进去。

**③ 情绪偏移（共振层的一部分）**

在不换固定层的前提下按本条稿子的情绪调温度（更暖 / 更暗 / 居中），字体与图标固定不动。**反标签化护栏**：温度跟**这一篇**的情绪基调走（冷峻拆解 / 恐慌下杀 / 温和叙事），不按品类标签套调性——先判断本篇的情绪温度，再定偏移方向。
